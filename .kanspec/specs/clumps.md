# clumps

## Rules
- Functions are the metrics pass's units of Source files (never Test files), read off its trees in `scan` and one parse per file in `scry clumps`. Per function: its name as metrics reports it (`Type.method`), its named parameters in declared order with their type text (Rust `parameter pattern:(identifier) type:`, Python `identifier` / `typed_parameter` / `default_parameter` / `typed_default_parameter` with `type` when annotated, TS `required_parameter` / `optional_parameter` with the `type_annotation` text after `:`, whitespace-normalized), receivers (`self`, `cls`, `this`, Rust `self_parameter`) never a slot, destructured and variadic parameters no slot, at most `max_params` (8) slots; and every identifier its body references (`identifier`, `shorthand_field_identifier`, `shorthand_property_identifier` nodes, plus `{name}` / `{name:` captures inside a string literal under a macro `token_tree`).
- Left out (`skip_trait_impls`, on): Rust functions under an `impl_item` with a `trait:` or under a `trait_item`, Python methods of a `class_definition` with `superclasses:`, TS `method_definition`s of a class with `class_heritage`, and arrow functions whose parent is `arguments` (callbacks). Always left out: units with no `body` (`function_signature_item`, TS overload signatures, abstract / interface signatures), Rust `#[cfg(test)]` regions and `#[test]` fns (see `regions`), Python `@overload` definitions (`skip_overloads`), `__dunder__` names (`skip_dunder`) and stub bodies (only `...` / `pass` / a docstring), and any function whose parameter names cover a `protocol_tuples` entry (`(c, next)`, `(req, res, next)`, `(ctx, param, value)`). With `dedupe_same_name_in_file` a second function of the same name in one file (cfg-gated twins) is not a second site. The totals note counts every skip.
- Every combination of `min_group` (3) ..= `max_group` (4) of a function's slot names, as a sorted tuple, is a group keyed repo-wide; its sites are the functions carrying all those names. A group is reported at `min_functions` (4) members or members in `min_files` (2) distinct files (`report_if_either`, on; off needs both).
- A slot agrees on type when at least one member annotates it and every annotated member's type text is identical; unannotated members never break agreement. A group is reported only when at least `min_typed_slots` (2) of its slots agree; a group no member annotates on any slot is reported instead at more than `min_functions` members when the joined names have at least `min_name_len` (3) characters (`sfa` = 3: a typed tuple of one-letter names is never gated by length).
- Reported groups with one and the same member set collapse into one clump whose tuple is the union of their names (the largest tuple those functions share, beyond `max_group` when they share more); a subset carried by more functions stays its own clump. Slots print in the first member's declared order (members sort by file, then line).
- A slot is unused in a member when the name starts with `unused_prefix` (`_`; empty turns that off) or the body references it nowhere; the clump carries `unused_slots` (`{slot: members}`, slots every member uses absent). With `note_single_caller` (on) a clump names `single_caller` when every member's bare name is referenced from exactly one function other than itself and any same-name function, and it is the same function for all members (text match only).
- The section line is ` 5 fns   2 files  (s: &Snapshot, f, a, _m: &Minter)  plan_start src/cmd/flow.rs:300, plan_ship :853, plan_park :938, plan_drop :1016, plan_repair src/cmd/repair.rs:79; _m unused in 5/5; f varies (&StartFacts, &ShipFacts, &Facts); a varies (…); all called from run`: agreeing types inline, varying slots bare with their distinct type texts first seen first, the path elided when it repeats the previous site's, `max_sites_listed` (8) sites then `+N more` (`functions[]` in `--json` has them all). Clumps sort by members desc, files desc, then tuple.
- Every file with a member gets one reason per clump, in the deliverable's wording: `parameters (s, f, a, _m) recur in 5 functions across 2 files (plan_start src/cmd/flow.rs:300, …, plan_repair src/cmd/repair.rs:79); `_m` is unused in all 5; `f` varies (&StartFacts, &ShipFacts, &Facts) - introduce a PlanInput struct or drop the slot` (`in 7 functions in this file` for a one-file clump, `` `x` is unused in 2 of 5 `` when partial, `; all called from `run`` when a single caller was found). The struct is named from the leading name pieces every member shares (`plan_*` -> `PlanInput`, `printEntry*` -> `PrintInput`), else `a shared input struct`; ` or drop the slot` (`slots`) only when a slot is unused in every member, never `remove`. At most `max_reported_per_file` (3) lines, then `(+N more parameter clumps in clumps)`; `clumps[]` (`[tuple, line]` per member function) sits on the hotspot in `--json`.
- Per file, `clump_members` (distinct member functions) is `signals.clump_members`, percentile-ranked with zero -> 0 and weight `[clumps].weight` (0.0: the section and the reasons print, the ranking is untouched). The CLUMPS section (after STRINGS) and `scry clumps <repo> [--json] [--top N]` print `8 clumps over 22 of 838 functions (2.6%) in 10 files; 10 functions (1.2%) carry a _-prefixed parameter`, the skip note, then the clumps, `--top` respected, `none` when no function was analysed or no clump was found; the subcommand also lists the files by members with their reasons. There is no silenced-parameter section of its own: the unused count is an attribute of a clump.
- JSON: `clumps: [{params, types, variants, functions: [{file, name, line}], files, unused_slots: {name: k}, single_caller, line}]` with `totals` (functions, in_clumps, clumps, files, silenced_functions, the four skip counts) and `notes`.
- Every floor, cap, list and switch above is a `[clumps]` setting in `scry.toml`.
