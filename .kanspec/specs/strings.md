# strings

## Rules
- Literals are collected from Source files only, on the metrics pass's trees in `scan` and one parse per file in `scry strings`: Rust `string_literal` and (with `include_raw`) `raw_string_literal`, inside `macro_invocation` token trees too; Python `string` with `interpolation` children as holes (a `concatenated_string` of adjacent pieces is one literal, its pieces joined); TS/TSX/JS `string` and `template_string` with `template_substitution` holes. Numeric literals (`integer_literal` / `float_literal`, `integer` / `float`, `number`) are collected for the `number` config class. A literal's text is what sits between its delimiters, as written.
- A literal is dropped when any ancestor is a `use_declaration` / `import_statement` / `import_from_statement`, a Rust attribute or TS decorator (`exclude_attributes`), a `#[cfg(test)]` region or `#[test]` fn (see `regions`), an assert-family macro, call or statement (`assert!`, `debug_assert_eq!`, `assert x, "m"`, `self.assertEqual(...)`, `expect(...)`, `assert.equal(...)`; `exclude_assert_calls`), a Python docstring position (the first statement of a module, class or function body; `exclude_docstrings`), a TS `import` / `export ... from` source or `require(...)` / `import(...)` argument, a `jsx_attribute` (`exclude_jsx_attributes`), or the direct argument of a `gettext_calls` call (`_`, `gettext`, `t`, …). A literal matching an `ignore_patterns` regex (as written or masked) is never collected.
- Masking: `{..}` and `${..}` holes, `%s`-style specifiers (`%-5.2f`, `%d`; `%%` stays `%`) and digit runs each become one `#`; `{{` / `}}` become one brace; the text is lowercased, whitespace runs collapsed and trimmed. The masked text is the exact-family key; the family prints the first site's text as written.
- Prose class: the masked text has at least `min_len` (20) characters and `exact_min_words` (2) whitespace-separated words, the written text does not match `nonprose_regex` (format strings, ALL_CAPS names, paths, URLs, header-like `content-type` words), and, with `require_message_role` (on), the literal is in a message role: an argument (at any depth inside the enclosing function) of a `message_macros` macro by last path segment (`format!`, `println!`, `eprintln!`, `write!`, `writeln!`, `anyhow!`, `bail!`, `panic!`, the assert family, a macro nested inside another macro's token tree by its `name!` tokens), a call or macro whose callee has a `message_calls` piece (`print`, `console.log`, `self.logger.info`, `logging.warning`, `warnings.warn`, `log::warn!`, `tracing::info!`), a `raise` / `throw` statement (when `raise` / `throw` are in `message_calls`), or a `return` / `Err(...)` value. An exact family is one masked text with sites in at least `min_files` (3) distinct files.
- Config class, tried when the prose rule fails: the written text matches a `config_patterns` regex, in `config_classes` order (`strftime` `%[YmdHMS]`, `env_name` `^[A-Z][A-Z0-9_]{5,}$`, `url`, `mime`, `path`), in any position; a string family is one text in at least `config_min_files` (2) files whatever roles it sits in. A number is a candidate when it is a float or an integer at or above `number_min` (100), not in `ignore_numbers` (`0, 1, 2, 10, 100, 1024`), and sits in a config role: the value of a Rust `const` / `static`, a struct `field_initializer`, a TS object `pair` or top-level `const` declarator, a Python `keyword_argument`, `default_parameter` or module-level assignment, or the direct argument of a builder call (`.timeout(300)`, the method name is the role); a plain wrapping call (`Duration::from_secs(300)`) is looked through to the role outside it. Numbers form a family only with the same value and the same folded role name (`_` and `-` removed, lowercased: `fetch_max_age_secs` = `fetchMaxAgeSecs`) in another file; `240` as `cache_age_secs` and as `DETAIL_MAX` never meet.
- Near-duplicate pairs: two distinct masked prose texts, each with at least `min_words` (3) words, bucketed by the words each has whose document frequency over distinct texts is at most `rare_word_df` (40), with word-set Jaccard in [`near_jaccard` (0.8), 1.0); at least one site of one lies in a file no site of the other does. Printed with each text's first site, Jaccard desc then texts; with `near_info_only` (on) they are information: never a reason, never counted.
- Per file, `family_literals` = literal sites in exact prose families plus sites in config families (plus near-pair sites when `near_info_only` is off); it is `signals.family_literals`, percentile-ranked with zero -> 0, weight `[report.weights] strings` (0.0 in both tables by default: the section and the reasons print, the ranking is untouched). Hotspots carry `repeated_literals[]` (`[family text, line]`) in `--json`.
- Reasons on the file, message line first: `9 of its strings recur elsewhere: "kanspec show {id}" (line 314) is spelled in 10 files (20x) - centralise the hint and message text` (the count is the file's sites in exact prose families; the example is its family with the most files, then occurrences). Then one line per config family the file is in: `timestamp pattern "%Y-%m-%dT%H:%MZ" (line 422) is duplicated in src/cmd/proposal.rs:426, src/logentry.rs:23, src/scan.rs:200 and src/scan.rs:972 with no shared constant; repo also formats time 4 other ways`, where the tail is ` - use TS_FMT from src/logentry.rs:23` when any occurrence is the value of a named constant (Rust `const` / `static`, TS top-level `const`, Python module-level ALL_CAPS), and the `repo also formats time N other ways` clause counts the other distinct `strftime` texts kept in the repo; numbers read `number 300 as fetchmaxagesecs (line 134) is duplicated in src/cache.rs:356 …`. At most `max_reported_per_file` (3) lines, then `(+N more repeated-literal families in repeated_literals)`.
- Every family lists every `file:line` (`sites[]` in `--json`; the section line shows `max_sites_listed` (8) then `+N more`) and its `named_const` (`; const TS_FMT at src/logentry.rs:23` on the line). Families sort by files desc, occurrences desc, then text (then role), so `--top` is stable; the section line is `10 files  20x  "kanspec show {id}"  src/cmd/flow.rs:314, …`, with `timestamp pattern "…"` / `env name "…"` / `URL "…"` / `MIME type "…"` / `path "…"` / `number 300 as fetchmaxagesecs` heads for config families.
- The STRINGS section and `scry strings` print the totals line `760 message literals of 1256 prose, 192 in 52 exact families (15.3% of prose); 88 config literals, 31 in 12 families; 4 near-duplicate pairs` (`prose_family_share` = prose sites in exact families / `prose_shaped`, the literals passing the prose rule whatever their role, so the share is comparable across repos with different message-role habits), the notes, the exact families, a CONFIG sub-list and a NEAR sub-list, `--top` respected, `none` when no literal was kept; `scry strings <repo> [--json] [--top N]` also lists the files by `family_literals` with their reasons.
- Every floor, list, regex, class pattern and switch above is a `[strings]` setting in `scry.toml`; an invalid regex is reported on stderr and ignored, never a panic.
