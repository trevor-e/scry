# comments

## Rules
- One walk per Source file on the metrics tree (`metrics::analyze_all_with` hands the root, the test regions and the units with their nodes): the root's direct children for banners, the body of every unit at or above the cognitive floor for phases. No second parse, no git, no graph. Test files are unranked and never read.
- A top-level comment is a comment node whose parent is the file root (`source_file`, `module`, `program`); comments inside `mod x { }` sit under `declaration_list` and never count. Rust doc comments (any `*_doc_comment_marker` child) are never banners or phases.
- A banner is a top-level comment whose text (marker stripped: `//`, `#`, `/* */`; a block comment's first non-empty line) matches `^\s*[rule]{min_rule_len,}\s*(\S.*?)?\s*[rule]*$` with `rule` = `[comments.banners].rule_chars`, or the short form `^\s*(──|--|==)\s*\S.*$`. Rule characters are counted as characters, never bytes: `──` is two, so two box-drawing characters never satisfy `min_rule_len = 6`. Text starting with a `skip_markers` entry (`#region`, `#endregion`, `%%`), or that is exactly one with its `#` dropped (a bare `endregion`), is not a banner; a title merely starting with a marker's word (`region handling`) is a title.
- Banners within `pair_gap` lines of each other merge into one boundary when only comments lie between them, so a rule / title / rule triple is one boundary and two rules separated by code are two. A boundary's title is the first inline rule text (rule characters and whitespace trimmed, at least one alphanumeric), else the first non-banner comment line inside the pair. With `require_title` an untitled boundary is dropped.
- With `skip_top_of_file`, a boundary whose first line is 1-3 and whose next non-comment top-level item is an import (`use`, `extern crate`, `import`, `from … import`) is a license or file header and is dropped, together with the next boundary when no item lies between them (the closing rule of a long header).
- Sections are one per boundary: `start` is the line after the boundary's last comment line, `end` the line before the next boundary's first line (EOF for the last, the last line counted whether or not the file ends in a newline), `lines` the span's lines outside inline test regions (see `regions`; the union, as the report's size signal subtracts them), `functions` the metrics units outside test regions whose start line lies in the span. A test region that closes the span (the `#[cfg(test)] mod tests` ending a file) pulls `end` back to the line before it, so the largest section and the split it names are production code. With `[tests].inline_modules` off the regions are source here as in the size signal. A boundary on the file's last line, or immediately before the next boundary, heads no section. The lines before the first boundary (imports, module docs) are no section.
- A file `qualifies` when `lines >= min_file_lines`, `sections >= min_sections` and the largest section has `>= min_section_lines` lines. Its annotation prints when it also sits at or above `min_size_percentile` (0-100, ranked among Source files on the report's size signal: lines minus inline test lines, the latter 0 when `[tests].inline_modules` is off), or when it is in the printed hotspot list whatever its percentile.
- The banner annotation is a per-hotspot reason line and carries no score: `scan.rs is cut into 4 labelled sections: 'The seals' 62-232, 'The ladder's value types' 236-310, 'The ladder' 314-978 (665 lines, 16 fns), 'The recorded human override' 982-1343 — extract the largest as ladder.rs`. Every section is named with its span; the largest carries its line and function count and names the suggested file (the title's first two content words, articles, `of`, `and` and single letters left out, lower-cased, with the file's extension: `Writes — the SAME rules` → `writes_same.rs`). A `mod.rs` / `index.*` / `__init__.py` is named with its directory. `--json` carries `sections[]` (`name`, `start`, `end`, `lines`, `functions`) on the hotspot, empty when the annotation is not printed for it.
- Phases run only for units whose cognitive is at or above `[comments.phases].cross_with_cognitive_min`; unset (the default) the gate is the report's own: cognitive over `[metrics].cognitive_hard`, so a unit exactly at the threshold, which has no `over cognitive` reason for the sub-line to ride on, gets none and `--json` agrees with the text. Units shorter than `min_span_lines` and, with `skip_test_modules`, units inside a Rust test region (see `regions`) are skipped; a unit whose body is not a statement block (an expression-bodied arrow function) has no phases.
- A phase comment is a non-doc comment whose parent is the unit's body block or a block at most `max_depth` levels below it (Rust `block` / `match_block`, Python `block`, TS `statement_block` / `switch_body` / `switch_case` / `switch_default`; a TS `switch_body`, which holds only cases, and the brace block of a `case x: { … }` add no level, so a case clause is one level below the body), whose text matches one of `patterns` case-insensitively. Nested functions and closures are their own scope and are not entered. The defaults are the box-drawing rules `^\s*[─═━]{2,}\s*\S`, `^\s*(step|pass|phase|stage)\s*\d` and `^\s*\d+[.):]\s`; `--` / `==` rules and ordinal words are prose too often and are not defaults.
- A phase spans from its comment's line to the line before the next phase comment in the same block (hence the same depth), else that block's last line (the body's closing brace for the body). Phase lines exclude blank lines. Its label is the comment text with rule characters trimmed, cut at the first `:`, at most 40 characters.
- A unit is reported when it has at least `min_phases` phases, every phase has at least `min_phase_lines` lines and the unit spans at least `min_span_lines` lines.
- With `estimate_cognitive`, a phase's `est_cognitive` is the metrics walker re-run over the phase's statements (the named non-comment children of its block inside the span) with nesting re-based to 0.
- Shared locals are names bound by a parameter, a `let` / assignment / `for` pattern (lower-case initial: `Some`, `Point` are constructors) before a phase and read as an identifier in at least two phases that do not bind the name themselves; the unit lists them by first binding line, each phase the ones it reads, and the reason prints the count and the first `max_shared_locals_named` names, then `+N more`.
- The phase reason is a sub-line of the metrics `N function(s) over cognitive K; worst X at C` reason, one per reported unit, joined to that reason with a newline so `reasons[]` keeps one entry per finding; the text report indents continuation lines under the reason. Wording: `attention (lines 778-1065, cognitive 30) already labels 3 phases: YOU 786-912, AGENT 913-976, WATCHING 977-1065 — extract each as a helper (est. cognitive 15 / 5 / 10; 4 locals shared: s, you, agent, d)`; `no locals shared` when there are none; the estimate part is omitted when the knob is off. Never a standalone reason, never a score input. `--json` carries `phases[]` (`label`, `start`, `end`, `lines`, `est_cognitive`, `shared_locals`) on the unit in `worst_functions[]`.
- Rows are computed from byte offsets (a line-start index per file), never from tree-sitter `start_point.row`, on every node this pass reads.
- `scry comments <root> [--json] [--top N]` runs discovery and metrics and prints the totals, `BANNERS` (every qualifying file, with `(size percentile P: hotspot list only)` when below the percentile) and `PHASES` (reported units by cognitive), `none` when empty; `--json` is the pass output with every file's `sections` whatever the thresholds, `files` keyed by path in sorted order.
- Every threshold, pattern and marker list lives under `[comments.banners]` and `[comments.phases]` in `scry.toml`; `[comments.banners].enabled = false` turns the partition off.
