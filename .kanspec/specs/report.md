# report

## Rules
- The report is written for an LLM reader: every ranked item carries the reasons it ranked, with symbol names and line ranges, never a bare number.
- Each analysis pass has a standalone subcommand (`files`, `history`, …) so a signal can be inspected on its own before it is folded into the composite score.
- Every signal is percentile-ranked within the repo's Source files before weighting; a file with a zero signal gets 0, not its tie percentile, so untouched files never score on churn.
- With history (defaults): score = 100 × (0.45·√(churn·complexity) + 0.15·fixes + 0.15·complexity + 0.10·coupling + 0.10·clones + 0.05·size + 0.05·dead), ×1.15 when `test_units` is 0. Without history the churn terms are dropped and complexity is weighted 0.55 (`dead` stays 0.05). `dead` is the percentile of `signals.dead_ratio` (see `dead`), 0 when the file has no dead lines.
- complexity = 0.6·pct(max cognitive) + 0.4·pct(total cognitive); coupling = max(pct(fan_in), 0.6 if in a cycle).
- `signals.test_units` is the number of test units naming one of the file's symbols (see `mentions`), raised to at least 1 when a test file imports the file or a test file's normalised stem equals the file's stem *and* the test sits in the same directory tree (the test's path above its first test-directory component is an ancestor of the file). An inline `#[cfg(test)]` module counts only through the units inside it that name a symbol of some file.
- The no-tests multiplier applies iff `test_units == 0`, as a step: no partial multiplier by count. Such a file gets the reason `no test unit names any of its symbols`: it is a mention/import/stem signal, not coverage, and a parent's test may still exercise the file; a file with any evidence gets no test reason from that rule.
- A file with at least `[tests].unmentioned_min_symbols` (3) public symbols whose share of them named by no test unit is at or above `[tests].unmentioned_share_reason` (0.5) gets `4 of 6 public symbols are named by no test: router (lines 204-229), request_ctx (lines 243-257)`: the first five in line order, then `, +N more`; `unmentioned[]` on the hotspot carries them all in `--json`, with `signals.public_symbols` as the denominator.
- History counts as present only when at least one commit joined a discovered file; commits that touched nothing we track (subdirectory scans, shallow clones) fall back to the static weights, and `scan` warns.
- Hidden coupling = co-change pairs where neither file imports the other, minus the explained ones; at most `[report].reason_hidden_partners` (2) partner reasons per file, hidden partners first and explained ones with whatever budget is left, as `changes together with X (4x, 3.5x more often than chance; 2 sweep commits ignored) but neither imports the other`: the non-sweep count, lift to one decimal, and the sweep commits left out of that count (clause omitted when none were).
- A pair is `explained_by` a file f when both members import f and f changed in ≥ `[history].explained_min_share` (0.5) of the pair's non-sweep co-commits (the file both import that changed in the most of them wins). Explained pairs leave `hidden_coupling` for `explained_coupling`, print under an EXPLAINED sub-heading with the same `(2 sweep commits ignored)` note as hidden rows, and their reason reads `changes together with X (5x): both import src/ctx.rs, which changed in 4 of those commits`. HIDDEN COUPLING says `none` only when both lists are empty.
- When the window had sweep commits the HIDDEN COUPLING section ends with `5 directory-sweep commits (>= 50% of src/cmd) excluded from pair counts; still counted as churn` (`sweep_note` in `--json`, `summary.sweep_commits` for the count); every hidden or explained pair carries `together`, `together_nonsweep`, `lift`, `explained_by` and `explained_commits` in `--json`.
- The `directories` section rolls Source files up by directory with the largest file named, so "largest file per module" is answered without ranking data files.
- Every weight, the no-tests multiplier, the cycle coupling floor and every reason threshold are `[report]` settings in `scry.toml`; `scry config` prints the effective values. With no file present the score is unchanged from the constants it replaced.
- Inline test regions come from metrics data, never a string search: the size signal, the summary's `source_lines` and the directory rollup use `lines - inline_test_lines`; `signals.inline_test_lines` and `test_regions[]` are in `--json`.
- A hotspot whose inline test ratio (`inline_test_lines / lines`) is at or above `[tests].report_inline_ratio_above` (0.5) prints `N in #[cfg(test)] mod at a-b` after its line count (`inline_test_note` in `--json`): the largest region's kind and range, then `, +K more` when there are others (every range is in `test_regions[]`); below the ratio, the plain line count.
- The churn reason prints `0 authors (all bot commits)` for a file only bots touched, and at `reason_bus_factor_min_commits` commits such a file gets `no non-bot author over the window (bus factor 0)` where one author gets `single author over the window (bus factor 1)`.
- The clone reason's table and logic percentages sum to its headline percentage (the headline is rounded once, the logic share is the remainder); the reason counts lines, not the `table_weight`ed ratio the gate uses. It ends with the file's largest pair, both sides as `symbol (lines)` with the other side's file when it differs: `18% of its lines are duplicated elsewhere (192 lines); largest: park (932-962) <-> drop_ticket (1010-1036), 239 tokens`.
- Every hotspot carries `plan[]` and `plan_more` (see `plan`), and the text report prints a `PLAN` block after the reasons of each printed hotspot (`1) park (932-962) duplicates drop_ticket (1010-1036), 239 tokens: keep one`, …, `(+N more)`) unless `[plan].include_in_text_report` is off or the plan is empty. `scry plan <file>` prints one file's plan on its own.
- A Source file whose inline test ratio is above `[tests].reclassify_file_above_ratio` (0.9) is a Test file for ranking: never a hotspot, counted under `test_files`.
- The dead pass's reasons for a file (dead and test-only symbols, the in-file-only line, dead shapes; see `dead`) follow the test-mention reasons on the hotspot; `dead_symbols[]` and `dead_shapes[]` are on the hotspot in `--json`. DEAD SURFACE prints after CLONES: the totals line, the pass's notes (the knip line for TypeScript), then the top files by dead lines as `lines ratio  dead/test-only/in-file-only of items  path`, `--top` respected, `none` when nothing was indexed; `dead` on the report carries totals, modes, notes and those rows.
- The helpers pass's reasons (same-name families this file defines a copy in, helper bodies it inlines; see `helpers`) follow the dead reasons; `signals.helper_copies` and `signals.inlined_idioms` sum into one percentile term with weight `[helpers].weight` (0 by default, so the HELPERS section and the reasons print without moving the ranking); `helper_copies[]` and `inlined_idioms[]` sit on the hotspot and `helpers` (totals, notes, top families, top inlined helpers) on the report. The HELPERS section prints the totals line, the attribution note, one line per family (verbatim / similar with every copy and its relation, different-contract as signature info) and an INLINED sub-list; `none` when no unit was found.
- The strings pass's reasons (the message-family line, then config-literal lines; see `strings`) follow the helpers reasons; `signals.family_literals` is percentile-ranked with weight `[report.weights] strings` (0 by default in both tables, so the STRINGS section and the reasons print without moving the ranking); `repeated_literals[]` sits on the hotspot and `strings` (totals, notes, top exact families, top config families, top near pairs) on the report. STRINGS prints after HELPERS: the totals line, the notes, one line per exact family, a CONFIG sub-list and a NEAR sub-list (information only); `none` when no literal was kept.
- The clumps pass's reasons (one per parameter clump this file has a member in; see `clumps`) follow the strings reasons; `signals.clump_members` is percentile-ranked with weight `[clumps].weight` (0 by default, so the CLUMPS section and the reasons print without moving the ranking); `clumps[]` (`[tuple, line]`) sits on the hotspot and `clumps` (totals, notes, top clumps, the unused prefix) on the report. CLUMPS prints after STRINGS: the totals line, the skip note, one line per clump; `none` when nothing was analysed or found.
- The declared pass's unread-knob lines (one per config struct with unread fields, rolled up to the `[section]` when the parent field is unread; see `declared`) follow the clumps reasons on the declaring file's hotspot, and its test-seam lines (one per env name production code reads that only tests set) follow them on every file holding a read; `signals.unread_knobs + signals.test_seams` is percentile-ranked with weight `[declared].weight` (0 by default, so the DECLARED section and the reasons print without moving the ranking); `unread_knobs[]` (`[section.knob, line]`) and `test_seams[]` (`[name, line]`) sit on the hotspot and `declared` (totals, notes, top orphans, misplaced deps, dead features, noop features, unread knobs, test seams) on the report. DECLARED prints after CLUMPS: the totals line, the notes, then ORPHANED DEPS, MISPLACED, DEAD FEATURES, UNREAD KNOBS and TEST SEAMS sub-lists, each only when non-empty; `none` when nothing was found. Manifests are not Source files and never rank.
- Units tagged `in_test` never head a worst-function reason or appear in `worst_functions`, and are left out of the summary's function counts.
- CYCLES prints one block per file cycle: `15-file cycle in src: cheapest cut src/paths.rs -> src/plan.rs imports 1 symbol (EntityRef, line 16) -> largest remaining cycle 12; hub cut: drop paths.rs's 4 imports (9 symbols) -> 11; no single import breaks this cycle`, then its members and, when the greedy set dissolves it, `cut set of 2 imports dissolves it: a -> b (X), c -> d (Y)`. A wildcard edge reads `>= 20 symbols (*, …)`; a cycle carried only by TS type-only imports says `N type-only imports ignored, largest runtime cycle 1; no runtime cycle`; a cycle below `[deps].min_cycle_size_to_cut` or a Rust cycle with `cut_rust_cycles = false` prints only `3-file cycle in src`.
- With `[deps].dedupe_cycle_reason` (default) a member's reason is `in the 15-file src cycle`, and the two files of the cheapest cut edge carry it: `in the 15-file src cycle (cut: paths.rs -> plan.rs, EntityRef)`; the old `in an import cycle of 15 files` on every member is what `dedupe_cycle_reason = false` prints. When type-only imports carry part of the cycle the reason says what CYCLES says: `in the 6-file src cycle (type-only, no runtime cycle)` when nothing is left at runtime, else `in the 17-file src/jsx cycle (runtime cycle 4; cut: a.ts -> b.ts, X)`. A cycle with no common directory reads `in the 3-file top-level cycle`. Cuts never change the score.
- The naming pass's attribute (a far-lived one-letter binding of a unit over the threshold, in `worst_functions` or at least `[naming].min_unit_lines` long; see `naming`) is a sub-line of the `N function(s) over cognitive K` reason after the phase sub-lines, or hangs under `N function(s) carry a one-letter name across a use gap of 30+ lines` when the file has no such reason; `signals.long_short_bindings` and `signals.short_binding_share` ride the hotspot and the share is percentile-ranked with weight `[naming].weight_into_complexity` (0 by default, so nothing moves). `worst_functions[].short_bindings[]` carries every short binding of those units in `--json`.
- The `N function(s) over cognitive K; worst X at C (lines a-b, nesting n, L locals)` reason names the worst unit's `locals` (see `metrics`), chooses that unit by cognitive, then locals, then lines, and appends ` — brain method: 258 lines, cognitive 42, 34 local variables; longest-lived p (lines 690-884), …` when the unit meets the three `[metrics].brain_*` floors; the label is text only (no section, no weight) and `locals` / `brain` / `longest_locals[]` ride `worst_functions[]` in `--json`.
- The fallback pass's reasons (one per production unit swallowing `[fallback].min_sites`+ parse failures with literal defaults, bare name outside `exempt_fn_patterns`, most sites first, at most `max_reported_per_file` per file then a `+N more` line; see `fallback`) follow the cognitive / naming reasons and precede the cycle reason: `parse swallows 5 parse failures with literal defaults (lines 157, 160, 161, 162, 163): a malformed line becomes header "", hash "", author "", ts 0 and subject ""`. No signal, no percentile, no weight: nothing moves; `worst_functions[].parse_defaults` / `fallbacks` / `fallback_sites[]` ride the hotspot in `--json`.
