# plan

## Rules
- The plan is built after every pass, from report input only: no new analysis, no git, no graph work. One tree walk per file with a clone run, in the clone pass, names its runs.
- Every clone run (both sides) resolves to `symbol`: the innermost metrics unit (see `metrics`; the same walk and the same names, `park`, `Store<'c>.transact`) whose `[start_line, end_line]` holds the run's start line; else, with `[plan].symbol_fallback = "preceding_item"` (default), the nearest preceding top-level named item, else `?`. Fallback items: Rust `function_item | impl_item | struct_item | enum_item | static_item | const_item` (an impl is named by its type text), TS `function_declaration | class_declaration | lexical_declaration` (through an `export_statement`), Python `function_definition | class_definition` (through a `decorated_definition`) and an `expression_statement` holding an assignment. An item starts on its first outer attribute (`#[derive(Debug)]` above a struct), and items inside a test region the clone tokenizer skipped are never fallback candidates: the `#[test] fn` above a struct does not name the struct's impl. `symbol_fallback = "none"` prints `?` for every run no unit holds.
- Step kinds: `fold_test_clones`, `canonicalise_clone`, `extract`, `cut_cycle_edge`; a pass that lands later adds its own kind. `table` (see `clones`) is a tag printed after a symbol, not a kind.
- A clone run whose start lies inside an inline `#[cfg(test)]` region (see `regions`) or in a Test-classified file (a discovery Test file, or a Source file reclassified by `[tests].reclassify_file_above_ratio`) never becomes a `canonicalise_clone` step, and neither does the pair it belongs to. With `[plan].fold_test_clones` (default on) the file's runs in test code become at most one `fold_test_clones` step: `fold 19 clone runs in #[cfg(test)] mod at 1284-2307 into shared test helpers`, naming the region holding the most runs and counting the rest (`, +2 in other test regions`). Off, those runs are left out of the plan. With the clone tokenizer stripping regions (`[tests].inline_modules`, default on) no run lies in a region, so the step only fires when that knob is off.
- `canonicalise_clone` steps are one per remaining pair, descending tokens (then line): `park (932-962) duplicates drop_ticket (1010-1036), 239 tokens: keep one` within one file; `att (1080-1097) duplicates src/rulesdoc.rs render_text (577-594), 103 tokens` across files, naming the other file and never picking a canonical copy. A table pair prints `table` after each symbol.
- `extract` steps: one per source unit with cognitive > `[metrics].cognitive_hard`, descending cognitive: `extract from ladder (cognitive 32, lines 405-656, nesting 5)`. Units tagged `in_test` never get one.
- `cut_cycle_edge`: only when the file's cycle has a cheapest single cut (see `deps`) whose source is this file: `cut the import src/paths.rs -> src/plan.rs: 1 symbol (EntityRef, line 16) -> largest remaining cycle 12`, P61's numbers and symbol names.
- Steps are ordered by `[plan].kind_priority` (default `fold_test_clones, canonicalise_clone, extract, cut_cycle_edge`), then by the metric within a kind; a kind left out of the list is not planned. The list is cut at `[plan].max_steps` (6) and the text report says `(+N more)`; `plan_more` in `--json` carries the count.
- No step carries a predicted score, ratio or rank: the percentile table makes such numbers wrong in sign as often as not.
- Every hotspot carries `plan[]` in `--json` (`n`, `kind`, `symbol`, `lines`, `target`, `text`) and `plan_more`; the text report prints a `PLAN` block under each printed hotspot when `[plan].include_in_text_report` (default on).
- `scry plan <file> [--root <repo>] [--json]` runs the scan pipeline on the root (`.` by default) and prints that file's plan: `plan for src/cmd/flow.rs:` then the numbered steps and `(+N more)`; `no plan` with exit 0 when the plan is empty or the file is not a ranked Source file (a note on stderr says so). A file that does not exist is an error.
- `max_steps`, `fold_test_clones`, `symbol_fallback`, `kind_priority` and `include_in_text_report` are `[plan]` settings in `scry.toml`.
