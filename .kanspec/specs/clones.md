# clones

## Rules
- Tokens are tree-sitter leaves with identifiers → `ID`, strings/JSX text → `STR`, numeric and boolean/null literals → `NUM`, comments dropped. Everything else keeps its node kind, so renamed copies match and reordered statements do not.
- Fingerprints are winnowed k-grams (K=30 tokens, W=20): any shared run of ≥ K+W-1 tokens is guaranteed to be found. Fingerprints seen in more than 40 distinct files are boilerplate and skipped; the cap is on files, not positions, so a periodic block copied into a handful of files is still found. A hard cap of 2000 positions bounds the pairing loop.
- Matches on one diagonal merge into runs, then each run is extended token-by-token in both directions while the tokens still match, so reported ranges are exact rather than fingerprint-sampled.
- Runs under `MIN_TOKENS` (70) are dropped. Per file pair, a run whose A-range and B-range both overlap a longer accepted run is the same clone at an offset and is dropped.
- Same-file runs whose two ranges overlap each other are repetition (tables, unrolled loops), not clones, and are dropped.
- A same-file run whose two ranges resolve to one container node (or nested ones) whose entries across both ranges form a uniform table (below) is that table matching its own second half: a uniform run longer than 2×`min_tokens` escapes the overlap rule on a clean diagonal. It is dropped as if never found, so it neither prints nor suppresses shorter runs under it (`drop_same_container_self_match`, default on). Two sibling items of one container that merely copy each other are not uniform and stay clones.
- A range resolves to the smallest named node spanning it, then down into any child spanning ≥ `dominant_child_share` (0.9) of its bytes: a run that spills a few tokens past its own item still resolves to that item, while the two halves of one container resolve to the container.
- Tagging, both sides of every surviving pair: from the resolved node upward, the first node with ≥ `table_min_entries` (6) consecutive same-kind named children under the range is the container (comments and Rust outer attributes are transparent). The entry kind is fixed for `match_block` (`match_arm`), `switch_body` (`switch_case`) and a `match_statement` block (`case_clause`); elsewhere it is the most common child kind.
- A side is a table when the dominant skeleton (named nodes only; identifiers, scoped paths, member/field/attribute chains, strings, numbers and booleans collapsed to one leaf) covers ≥ `table_min_dominant_shape` (0.6) of the entries, no entry contains a node in `table_control_kinds` for its grammar, and no entry has more than `table_max_entry_nodes` (40) named nodes. Rust `try_expression` (`?`) is never a control kind: it sits in every dispatch arm. A pair is `table` iff both sides are, else `logic`.
- Per file, `clone_lines` is the union of all reported ranges touching the file, split into `logic_clone_lines` (lines under a logic pair) and `table_clone_lines` (lines only under table pairs); `clone_ratio = (logic + table_weight × table) / lines`, `table_weight` 1.0 by default (0.25 dampens parallel maps). `tables[]` names each table touched: symbol, container kind, line span.
- Every pair carries `kind`, `container_kind` and `entry_count` (side A's, when table) and each side its `symbol`, the nearest enclosing named item (`fn`, `static`, `enum`, `let`, `const x =`); `--json` prints them all.
- With `list_tables_separately` (default on) the report's CLONES section lists logic pairs and then table pairs under a `TABLES` sub-heading with container kind and entry count, each list `--top` long; off, one list with table pairs annotated inline. A hotspot's clone reason states the split in whole percent and names each table: `17% duplicated lines were 11% registry table (CHECKS, lines 91-174) and 6% logic`.
- Pairs sort by tokens, then A file/line, then B file/line, so `--top` shows the same subset on every run.
- Only Source files are compared. Tests and fixtures duplicate by design.
- `k`, `w`, `min_tokens`, `max_files`, `max_locations`, `drop_same_container_self_match`, `dominant_child_share`, `table_min_entries`, `table_min_dominant_shape`, `table_max_entry_nodes`, `table_control_kinds` (per grammar: `rust`, `typescript`, `python`), `table_weight` and `list_tables_separately` are `[clones]` settings in `scry.toml`.
- Bytes inside an inline test region (Rust `#[cfg(test)]` mods/items, `#[test]` fns) emit no tokens, so no clone run can lie inside one; `clone_ratio` divides by the lines outside regions. `[tests].inline_modules = false` restores the old behaviour.
