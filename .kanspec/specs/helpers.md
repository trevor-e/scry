# helpers

## Rules
- Units are top-level free functions, consts and statics in Source files, collected on the metrics pass's trees: Rust `function_item` / `const_item` / `static_item` at module level (inside `mod` bodies too) with no `impl_item` or `trait_item` ancestor; Python module-level `function_definition` and `decorated_definition` (never `@overload`, never `__getattr__` / `__dir__`) and ALL_CAPS assignments; TS/TSX/JS `function_declaration` and `variable_declarator` with an arrow / function value directly under `program` or an `export_statement`, plus ALL_CAPS consts. Inherent-impl methods join only with `include_inherent_methods`, keyed `Type::name`; trait-impl methods never. A definition, or a whole `mod`, under `#[cfg(...)]` naming a `cfg_gate_attrs` entry (`unix`, `windows`, `target_os`, `target_family`, `feature`) or `test` is a platform twin and never a unit; Test files and inline test regions contribute units only with `include_test_helpers`.
- The helper normalizer (shared by both halves, not the clones one): comments dropped; only bound names become `ID`: parameters, `let` / `const` / `var` patterns, closure and lambda parameters, `for` targets, match-arm and `except … as` bindings, collected per outermost function-like node (nested closures share the set); callee, field, method, macro and path names, types and free names are kept verbatim, and so is every literal (a string, char, number, template or f-string is one token of its own text, with `{name}` / `{name:` captures of bound names rewritten to `{ID}`); a keyword-spelled identifier inside a Rust `token_tree` is a keyword. Bodies drop their outer braces, a leading `return` and a trailing `;`, so tail-expression and `return x;` forms match. Consts compare on their raw whitespace-split value text when `compare_consts_raw` (a one-literal const would otherwise look verbatim with every other).
- Families group units by exact name within one language family (Rust, Python, TS/JS never mix) across distinct files; a name shorter than `min_name_len` (4) or in `ignore_names` never forms one, and a family needs `min_files` (2) defining files. Every pair of copies in different files is classed: `verbatim` (equal signature, identical normalized bodies), `similar` (equal signature, 5-gram Jaccard >= `min_body_jaccard`, 0.5), `different contract` (parameter count or return-type text differ) or `divergent` (equal signature, Jaccard below the floor); a sequence shorter than five tokens compares whole. The family's class is its best pair. Without `report_divergent`, a copy of a verbatim / similar family whose every pair is divergent (same name and signature, nothing else) is dropped from the family before it is counted and printed. Signature = named parameter count + return-type text, whitespace-normalized.
- Twin suppression drops a family (counted as `suppressed_twins`, never listed) when two defining files share a basename in different directories (`jsx/base.ts` vs `jsx/dom/base.ts`; `suppress_path_suffix_twins`), when two defining files are linked by an import edge either way in the deps graph (a re-export wrapper, or a deliberate twin beside the module it imports: `jsx/dom/render.ts` imports `../base` and redefines `getNameSpaceContext`; `suppress_import_linked`), or when a defining file matches `sibling_dir_globs` (`**/adapter/*/**`).
- Verbatim and similar families print in the HELPERS section and put one reason on every defining file whose copy has a verbatim or similar partner: `defines plural (lines 469-475), also defined verbatim in src/cmd/flow.rs:430 and as plural(n, noun) in src/cmd/proposal.rs:168 - 3 copies from 3 commits / 2 sessions; hoist one`; every other copy is named with its relation to this one, partners first (`verbatim in`, then `similarly (Jaccard 0.71) in`, `as name(params) in` for a different contract, `differently (Jaccard 0.20) in` for a divergent one), the copy count comes before the attribution, and the line ends `hoist one`. A verbatim / similar family whose bodies are each a single `match` / `switch` over string arms with differing first-parameter types carries `(same match over N types)` after the count. Different-contract families are section-only info: `repo_relative: src/cmd/quirk.rs:300 repo_relative(ctx, p) -> String, src/scan.rs:946 repo_relative(ctx, p) -> Option<String> (Jaccard 0.1)`; divergent families print the same way only with `report_divergent`. The section sorts families by files x best Jaccard, then first path, then name.
- Attribution (`attribute_commits`, needs history: `--no-history` or no repository turns it off with an `attribution: off` note): each copy's introducing commit is the oldest commit `git log -S'<keyword> <name>(' -- <file>` returns (`-S'NAME '` for a Python module-level const, which has no keyword), its `Claude-Session` trailer's last path segment is the session id; the family counts distinct commits and distinct sessions. Verbatim / similar copies are looked up first, at most `max_git_lookups` (50) copies per scan, in parallel; the rest print without commits and the note says `capped`.
- Inlined idioms: every unit that is a function, not in `inline_ignore_names`, whose normalized body has `min_tokens` (12) ..= `max_helper_tokens` (40) tokens, at least `min_distinct_kinds` (3) distinct token kinds (bound name, kept name, number, string, keyword / punctuation), one keyword or operator and one kept name or literal, is a small helper; helpers with one name and one body are one idiom (`also defined at src/store.rs:254`). Its body is searched as an exact token sequence in every Source file's stream (same normalizer, one bound set per outermost function, inline test regions skipped and fenced with a sentinel), indexed by the first four tokens; a hit whose lines lie inside any definition of the same name (any file, any kind, per the symbol index) is that definition, not a copy. With `allow_one_wildcard` one `ID` slot of the helper may cover one expression-shaped token run at the hit (brackets balanced, no depth-0 `,` `;` `{` `}` `=>`, no longer than the helper; a single name or literal counts, a lone punctuation token does not: `n == 1` matches `e.rules == 1`, `open.len() == 1`, `COUNT == 1` and `2 == 1`, inside a macro's `token_tree` too), and the index is by first token.
- A helper is reported when its hits reach `min_occurrences` (2) across `min_files` (2) files; each hit maps to `file:line` through the token's line. A hit file can call the helper when the helper is not private and the file is in the same crate or package (the path up to its first `src` component, else its first directory) or already imports the defining file; `require_reachable` drops the other hits. Every hit file gets the reason `body of plural (src/cmd/status.rs:469-475) is inlined 2 times in 2 files instead of called: src/cmd/init.rs:156, src/cmd/done.rs:469` when it can call, else `… inlined 2 times in 2 files: … - plural is private; hoist and call`; a defining file's family reason gains `; its body is also inlined N times in M files instead of called` before `hoist one`. The section's INLINED list sorts by occurrences, then path; the repo stat is `inlined_helpers / small_helpers`.
- Per file: `helper_copies` (definitions in reported verbatim / similar families) and `inlined_idioms` (hits in the file) are `signals`, their sum percentile-ranked (zero -> 0) with weight `[helpers].weight` (0: the section and reasons print, the score is untouched); hotspots carry `helper_copies[]` (family names) and `inlined_idioms[]` (`[name, line]`) in `--json`, and `helpers` on the report holds the totals, the notes and the top families and inlined helpers. Reason lines per file are capped at `max_reported_per_file` (5), families first, then `(+N more helper findings in helper_copies / inlined_idioms)`.
- `scry helpers <repo> [--json] [--top N]` runs the pass alone (one parse per Source and Test file for this pass and the symbol index) and prints the totals line, the notes, the families with every copy's signature, commit and session, the inlined helpers and the files by copies and idioms.
- Every floor, cap, list, glob and switch above is a `[helpers]` setting in `scry.toml`; the callee-name and literal keeping of the normalizer is the rule, not a knob.
