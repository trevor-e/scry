# dead

## Rules
- The symbol index is built once per scan from every discovered Source and Test file (Data, Generated and Vendored files are never indexed), on the metrics pass's trees for Source files and one parse per Test file; never from the filesystem. `SymbolIndex` holds every definition (any visibility, production or test context) and, per file, references by bare name split into `prod` / `test`, plus doc-comment words; lookups by name (`definitions`, `samename`, `refs_in`, `refs_by_file`, `external_refs`, `doc_mentions`) are what later passes reuse.
- Definitions: Rust `function_item` / `function_signature_item` (`fn`, or `method` inside an impl or trait, qualified `Git::is_ignored`), `struct`, `enum`, `union`, `trait`, `type`, `const`, `static` and `mod` items at any depth, with their `visibility_modifier` (`pub` = public, `pub(crate)` / `pub(super)` / `pub(in …)` = restricted, none = private); TS/TSX/JS top-level `function`, `class`, `abstract class`, `interface`, `type`, `enum` and `const` / `let` declarators (public iff under an `export_statement`), class methods (private); Python module-level `def`, `class`, methods and assignments (public iff the name has no leading `_`).
- References are the identifier leaves by grammar (Rust `identifier`, `type_identifier`, `field_identifier`, `shorthand_field_identifier`, which covers `scoped_identifier` / `scoped_type_identifier` segments and every identifier inside a `token_tree`; TS `identifier`, `type_identifier`, `property_identifier`, `shorthand_property_identifier(_pattern)`, excluding anything under an `import_statement`; Python `identifier`, which covers `attribute`). A definition's own name node, a struct field's declared name and an enum variant's name are declarations, never references (excluded by byte range). A reference in a `token_tree` counts as prod or test by its enclosing context like any other.
- Doc mentions are the words of Rust doc comments (`line_comment` / `block_comment` with a `doc` field), TS comments and Python comments and docstrings; they never satisfy reachability and are printed in the reason.
- Test context is the union of discovery's Test classification, `[dead.test_only].extra_test_globs` (`**/testutil*.rs`, `**/test_utils*`, `**/fixtures/**`), `bench_globs` (`benches/**`, `examples/**`, `fuzz/**`, unless `treat_benches_as_prod`), Rust `#[cfg(test)]` regions and `#[test]` fns (see `regions`), TS calls named in `ts_test_calls` (`describe`, `it`, `test`) and Python `test_` functions and `pytest`-decorated definitions. A reference inside test context is `test`, everything else is `prod`; a definition inside it is never a candidate.
- Never candidates, though their references still count: private definitions, trait-impl methods, items under `skip_attrs` (`#[test]`, `#[tokio::test]` by last segment, `#[no_mangle]`, …), Python `skip_decorators` (`pytest.fixture`, `router.*`), `skip_names`, `skip_name_prefixes` (`_`, `test_`), TS `ts_framework_exports` (`default`, `loader`, …), items spanning fewer than `min_lines` (2) lines, symbol classes outside `kinds` (`fn`, `type`, `const`; `mod` opt-in), files matching `entrypoints` (always) and files matching `api_roots` (in library mode). They are counted as `exempt_items`.
- `mode = "auto"` resolves the nearest manifest above each file, read once per directory when `read_manifests`: a Cargo.toml with `[[bin]]` (or `src/main.rs` / `src/bin/`) is an application, one with `[lib]` (or `src/lib.rs`) and no binary is a library, a package.json with `exports` is a library, a pyproject without `[project.scripts]` is a library; no manifest means application. Cargo `[[bin]] path` and `[lib] path` and package.json `exports` / `main` / `module` / `types` / `bin` targets (`./dist/x.js` remapped to `src/x.ts`, wildcards as globs) become that manifest's entrypoints and api roots. Library mode exempts plain `pub` / `export` and checks only restricted visibility; `library` / `application` in the knob override every manifest. `scry dead` prints one `mode` line per manifest with what decided it.
- Per candidate: `external_prod_refs`, `external_test_refs`, `own_prod_refs`, `own_test_refs`, `doc_mentions`, `samename` (definitions sharing the bare name, any file, any visibility). DEAD = all four counts 0 and `samename == 1`; TESTONLY (strict) = `external_prod_refs == 0` and `own_prod_refs == 0` and `own_test_refs + external_test_refs >= [dead.test_only].min_external_test_refs` (2) and `samename == 1`; OVEREXPORTED = `external_prod_refs == 0` and `own_prod_refs > 0`; AMBIGUOUS = would be DEAD or TESTONLY but `samename > 1`. Any production reference, even in the defining file, demotes to OVEREXPORTED; a name defined twice merges its references and can only hide a hit, never create one.
- `string_refs` (default on): a string literal references `name` when the whole string or a dot- or colon-separated segment of it equals `name` (`'app.apps.AppConfig'`, `'pkg.mod:func'`, `"hooks::install"`) or it holds `{name}` / `{name:` (a Rust 2021 inline format argument is string content inside a `token_tree`, not an identifier: `format!("{BIN_ENV}")` keeps `BIN_ENV` alive). Off only by knob.
- Python never gets the in-file-only line. TypeScript is checked only under an explicit `mode = "application"` with `typescript` in `languages`; otherwise the section carries one note pointing at knip. `languages` defaults to `["rust"]`; unchecked languages get a note with their exported count.
- Per file: `pub_items` (candidates), `dead_count`, `test_only_count`, `overexported_count`, `ambiguous_count`, `own_file_only_share = overexported / pub_items`, `dead_lines` (union of the line ranges of candidates with `external_prod_refs == 0`) and `dead_ratio = dead_lines / (lines - inline_test_lines)`. `dead_ratio` is `signals.dead_ratio`, percentile-ranked with zero -> 0 like every other signal, weight `[report.weights] dead` (0.05 with and without history, a new term).
- Reasons on the file, in this order: per-symbol lines, DEAD before TESTONLY, longest line range first, at most `[dead.symbols].max_reported_per_file` (5; TESTONLY lines also capped by `[dead.test_only].max_reported_per_file`), then `(+N more dead or test-only symbols in dead_symbols)`. DEAD: `pub fn install (hooks.rs 143-147) is called nowhere in 81 files (5 doc mentions)` (`referenced nowhere` for non-functions; the file count is the indexed files of that language). TESTONLY: `pub fn Git::is_ignored (git.rs 833-835) has no production caller: 4 uses, all in tests/git_real.rs, tests/lock.rs; move into the test crate or delete`, naming every file with a test reference; `#[cfg(test)]` is suggested only when every referencing test is the file's own inline test (`all in its own #[cfg(test)] tests; move under #[cfg(test)] or delete`), never for a caller under `tests/`. AMBIGUOUS: `pub fn parse (cli.rs 40-88) shares its name with 7 other definitions; reachability not assessed`. When every one of a file's (two or more) candidates is TESTONLY, one rollup replaces the per-symbol lines: `all 6 exported symbols in transitions.rs are test-only (lines 195-234), kept alive by tests/transition_table.rs`.
- OVEREXPORTED is never a per-symbol reason and never says "narrow to private": one per-file line, gated on `pub_items >= overexported_min_items` (4) and `own_file_only_share >= overexported_min_share` (0.5), ranked against every checked file: `12 of 13 pub items are referenced only inside this file (92%, 99th percentile): Assets (line 56), AppState (lines 59-68), Tick (lines 78-81), ApiError (line 86) and 8 more` (the first `max_reported_per_file` in line order).
- Dead shapes (Rust only, `[dead.shapes]`, inside the same walk): a struct or enum is a candidate when it is not in test context, every derive is in `allow_derives` or `serializing_derives` (`Serialize` reads every field but constructs nothing: such a struct has no never-read field, such an enum is still checked), it carries no `skip_attrs` (`repr`) and, with `require_type_reachable`, the type has a production reference outside its file. Field reads: `field_expression field:` not on the `left:` of an assignment, `field_pattern` names, any identifier inside a `token_tree`, `{name}` captures in a macro string; writes: struct-expression initialisers (shorthand too) and assignment left sides. A field with `reads == 0` prints `field Ticket.mtime (model.rs 81) is written at 9 sites (store.rs 870, derive.rs 1339, ...) and never read`; `_`-prefixed fields never.
- Variants: a scoped path (`scoped_identifier`, `scoped_type_identifier` under a `struct_expression`) is a match in pattern context (nearest ancestor a pattern node, a `match_pattern` outside its guard, or the `pattern` field of `let`, `if let` / `while let`, `for`, a parameter or closure parameter) and a construction otherwise; `Self::V` is a scoped path like any other; a `use …::Enum::*` at any scope makes every bare mention of the variant's name in that file a construction; identifiers in a `token_tree` and `{name}` captures construct. An enum with an `impl Trait for Enum` where the trait is in `exempt_impl_traits` (`FromStr`, `TryFrom`, `From`, `Default`, `Deref`) or `#[derive(Default)]` is exempt. `constructions == 0` and `matches > 0` prints `variant Color::Blue (out.rs 387) is matched at out.rs 402 but never constructed: a state nothing produces` (off with `report_handled_never_produced = false`, or under `#[non_exhaustive]` with `non_exhaustive_hides_handled`); neither prints `variant E::V (f.rs 10) is never constructed or matched`, which `#[non_exhaustive]` always hides. Same-named fields or variants on other types merge their counts (can only hide a hit). At most `[dead.shapes].max_reported_per_file` lines, then `(+N more dead shapes in dead_shapes)`; no score weight.
- The report's DEAD SURFACE section prints the totals line (`708 pub items checked in 82 files (98 more exempt: …): 1 dead, 6 test-only, 154 referenced only in-file (23% with no external production use); 4 dead shapes`), the notes, and the top files by `dead_lines` with `dead / test-only / in-file-only of pub items`; `none` when nothing was indexed. `--json` carries `dead` (totals, modes, notes, files) on the report and `dead_symbols[]` (every candidate with its category and the five counters) and `dead_shapes[]` on each hotspot. `scry dead <repo> [--json] [--top N]` runs the pass alone and prints the modes, the totals, the dead and test-only symbols longest first with their counters, the shapes and the files by dead lines.
- Every list, floor, mode and cap above is a `[dead.symbols]`, `[dead.test_only]` or `[dead.shapes]` setting in `scry.toml`.
