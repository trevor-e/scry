# declared

## Rules
- Manifests are the files matching `manifest_globs` (`**/Cargo.toml`, `**/package.json`, `**/pyproject.toml`) found by one walk of the root (gitignore respected, `.git` and the discover pass's vendor directories skipped, hidden files included); only `Cargo.toml` is parsed in this version, the others are counted in the totals and a note (`parse_cargo` is where the package.json / pyproject.toml readers plug in). The scope of a manifest is every Rust Source or Test file whose nearest ancestor manifest it is (nested manifest directories belong to their own manifest); its text form is the distinct first directories of those files (`src/ or tests/`, `crates/index/src/`). Every rule below is Cargo only, and `languages` without `rust` turns the pass off.
- Dependencies come from `[dependencies]`, `[build-dependencies]`, `[target.<cfg>.dependencies]` (and their `build-`/`dev-` forms); `[dev-dependencies]` count in the total but are checked only with `check_dev_dependencies`. The in-code name is the table key with `-` -> `_`, never the `package` value; a `workspace = true` entry inherits `package` from the nearest ancestor manifest's `[workspace.dependencies]` and is checked in the member's scope. The manifest line is found by text (`key = …` under the table, or a `[table.key]` header). Names matching a `side_effect_deps` glob (`*-sys`, `tikv-jemallocator`, `openssl`, `getrandom`, …) are never checked; the note counts them.
- A reference to crate `x` is the leftmost identifier of each leaf path of a `use` tree (`use x::{a, b as c, d::*}`, `use {x::y, z}`, `use ::x::a`), `extern crate x`, a `scoped_identifier` or `scoped_type_identifier` whose `path` is a bare identifier (or whose path is absent after a leading `::`), and inside every `token_tree` (attribute arguments, macro bodies, `macro_rules!` arms) an identifier followed by `::` that no path piece precedes (`#[derive(clap::Parser)]`, `lazy_static! { … rx::Re … }`, `::log::debug!`). References are split into production and test context: Test files, `#[cfg(test)]` regions and `#[test]` fns (see `regions`), and files a `#[cfg(test)] mod x;` resolves to (`x.rs`, `x/mod.rs`, `<stem>/x.rs`).
- An orphan is a checked dependency with zero references in its manifest's scope, Source and Test alike. With git (`scan` with history, `scry declared` on a checkout) each non-optional orphan is enriched, at most `max_git_lookups` (50) units in parallel: the birth commit of the manifest line (`git log -S<key> -- <manifest>`, oldest), its age in days to the newest commit and the commits since it, and whether the scope's history ever imported it (`git log -S'<ident>::' -- <scope dirs>`: the newest hit is the removing commit, the last commit touching the scope before it the last use). An orphan younger than `min_age_commits` (5) commits is not reported (a note counts them). The first `doc_globs` file (`*.md`, `docs/**`) naming the dep as a whole word (`-` and `_` are word characters) is the doc mention.
- The orphan line is `pulldown-cmark declared in Cargo.toml:39 since 988d9b5 (13 days, 101 commits) and never imported by any src/ or tests/ file; mentioned in ARCHITECTURE.md:2033 - wire it or drop it`: ` under [target.'cfg(unix)'.dependencies]` after the location when the table is not `[dependencies]`, `since …` only with git, `last used in <hash>, removed in <hash> (<date>)` when history imported it, `; mentioned in <doc>:<line>` when a doc names it, `; the crate silences warnings (#![allow] at <file>:<line>)` when the crate root carries `#![allow(warnings)]` / `#![allow(unused)]` (with `skip_lint_silenced_crates` such crates are skipped instead; a note names them either way). Orphans sort by commits since birth, most first, then manifest and line. An optional orphan (`optional = true`) counts in the totals and `orphans[]` but never prints its own line: the feature gating it prints it (P65); one gated only by a live or unreported feature is counted in a note.
- With `check_placement` a `[dependencies]` entry whose references are all in test context prints `tempfile is declared in [dependencies] (Cargo.toml:41) but its only 3 references are in tests/lifecycle.rs and a #[cfg(test)] module in src/store.rs - move it to [dev-dependencies]` under MISPLACED; off by default and never a hotspot reason.
- Features are the `[features]` entries other than `default`, plus cargo's implicit `x = ["dep:x"]` for an optional dep no feature names. An element `x/f` or `x?/f` forwards; `dep:x`, or the bare name of an optional dep no feature is named after, is a dep; a declared feature name is a sibling; anything else is unknown. Consumers are `feature = "<name>"` triples inside any token tree (`#[cfg]`, `#[cfg_attr]`, `cfg!`, `quote!`), `CARGO_FEATURE_<NAME>` string literals and `cargo:rustc-cfg=feature="<name>"` literals in a `build.rs` of the scope, `required-features` on `[[bin]]` / `[[example]]` / `[[test]]` / `[[bench]]`, and names under `[package.metadata.docs.rs]` / `[package.metadata.cargo-all-features]`. A feature is alive when it forwards, has a consumer, has an unknown element, or enables an alive sibling (fixpoint); noop when it has no elements and no consumer; dead when it is neither and every element is an orphaned dep or a dead sibling (fixpoint); a feature gating a dep that is referenced is alive. `features = ["x"]` on a path dep in another manifest is `; enabled by <manifest>` on the line, never a consumer; a `feature_ci_globs` file (`.github/workflows/*`, `Makefile`, `justfile`, `**/*.sh`) naming the feature adds `; consumed only by CI: <files>` and never suppresses.
- A dead feature prints when it gates at least one orphaned dep (`report_bare_dead_features` adds the ones that only enable dead siblings), is older than `min_age_commits`, and reads `feature ci-homerunner (Cargo.toml:26) gates optional dep rusqlite (Cargo.toml:58) and nothing in src/ or tests/ checks cfg(feature = "ci-homerunner"); its last consumer was removed in 9f2f0f7 (2026-09-02); the comment at Cargo.toml:23-25 says 'Moves into `default` when ci.rs lands'`: the killing commit is the newest `git log -S'feature = "<name>"' -- <scope dirs>` hit, `never consumed` without one, the comment clause is the last sentence of the `#` block right above the line. Noop features (`= []` with DEPRECATED comments) print only with `report_noop_features`; a note counts the suppressed ones. Every feature with its state, consumers, gates and CI files is `features[]` in `--json`.
- Config candidates are `Deserialize`-derived structs (a `derive` attribute naming `Deserialize`) outside test context that are the type target of a deserialise call in a `config_formats` crate (`toml::from_str::<T>`, `let c: T = toml::from_str(…)`; default `["toml"]`, so JSON payloads and YAML frontmatter need the file or name rule), or sit in a file matching `config_file_regex`, or match `config_struct_regex` (`(Cfg|Config|Settings|Options)$`); a `Deserialize` struct a candidate's field links to (a plain type, `Option<T>`, `Box<T>`, `Vec<T>`, a map value) is a candidate too, and that link is the section path (`Config.ci: CiCfg` -> `[ci]`, `CiCfg.homerunner: HomerunnerCfg` -> `[ci.homerunner]`, `#[serde(rename)]` honoured). Crates with no `[[bin]]`, `src/main.rs` or `src/bin/` are skipped under `require_bin_target` unless `config_is_public_api` (a note counts them). `#[serde(skip)]` fields are never knobs.
- Reads are counted in every Rust file by bare field name: `field_expression` fields that are not a call's function, `field_pattern` names in struct patterns, `index_expression` string keys, and inside any token tree an identifier after `.` not followed by a call (`format!("{}", cfg.plan.x)`). Excluded: `impl Default` / `impl Serialize` / `impl Deserialize` bodies, and methods named like the write side (`serialize_fn_regex`: `render`, `to_toml`, `serialize`, …) only when the `impl` block is for a candidate struct itself; `App::save(&self, c: &Config) { c.knob }` reads `knob`. Reads in test context count apart: a field with no production read and a test read prints `Config.unused (src/config.rs:4) is read only by tests`, never a finding. A field shorter than `min_field_name_len` (3) is skipped only when another candidate declares the same name.
- An unread field whose type is a candidate rolls up: `[ci.homerunner] (src/config.rs:182-204, 4 knobs: homerunner, bin, db, api) is deserialised from TOML under deny_unknown_fields and documented at docs/config.md:91-94, but no code reads any of them - the program accepts the section and ignores it`, the range from the field to the end of the child struct (its own file and range when it lives elsewhere), the knob count the field plus every descendant, `under deny_unknown_fields` when either struct says so. Unread scalar fields of one struct print one line: `[strings] (src/config.rs:726-792, 26 knobs) is deserialised from scry.toml, but no code reads max_sites_listed (line 789), display_text_len (line 791) - the program accepts it and ignores it` (`any of them` and `the section` when every knob is unread; the struct name instead of a section for a root struct's fields). The source is the first config-file-looking string literal of the root struct's file (`scry.toml`), else the deserialise format (`TOML`), else `a config file`; `documented at <doc>:<lines>` comes from a fenced block of a `public_doc_globs` file (`README*`, `docs/**`, `*.1`, `man/**`) holding the `[section]` header or a knob key (for a roll-up the header alone documents the section; for a scalar-field line the fence must name one of the unread knobs, a bare `[section]` header does not document them), the range from the header (or first knob) to the last knob line in that fence. With `require_sibling_read_or_doc` a line prints only when a sibling field of the struct has a production read or the knob is documented; a note counts the rest. `max_knobs_listed` (8) names then `+N more`.
- Env reads (every grammar, `languages` notwithstanding) are collected from Source files outside test context (Test files, `#[cfg(test)]` regions and `#[test]` fns by the tree, files a `#[cfg(test)] mod x;` names): Rust `env::var("X")` / `env::var_os("X")` as a call or as tokens inside a macro body, Python `os.environ["X"]` / `os.environ.get("X")` / `os.getenv("X")` (and the bare `environ` / `getenv` imports), TypeScript `process.env.X` / `process.env["X"]` / `Deno.env.get("X")`; a dynamic name is a false negative only. Compile-time reads (Rust `env!` / `option_env!`, as a macro or inside an attribute's token tree; `import.meta.env.X`) are counted in a note unless `include_compile_time_env`. Every read site carries `file:line symbol`, the symbol being the nearest enclosing metrics unit (empty at top level). Production setters are `env::set_var("X", …)`, `Command::env("X", …)`, a build script's `cargo:rustc-env=X=…` literal, `os.environ["X"] = …`, `process.env.X = …` and `Deno.env.set("X", …)` outside test context.
- Product prefixes are the uppercased, `-` -> `_` forms of Cargo `[package].name` and every `[[bin]].name`, package.json `name` (scope stripped), pyproject `[project].name` (these two are read for their name only) and `env_prefixes`; a manifest name in `env_prefix_stoplist` (`app`, `core`, `cli`, `server`) derives none. A name is a candidate iff it equals a prefix, starts with `<prefix>_`, or contains an `env_keywords` entry (`TEST`, `FIXTURE`, `SEED`, `MOCK`, `FAKE`, `STUB`, `REPLAY`; case-sensitive); a foreign name is never reported.
- Mentions are whole-word occurrences of the name in every discovered file's text (`_` is a word character; the index keeps the upper-case tokens that carry a `_` or a keyword), test context apart; docs and setter files are scanned by line. A candidate is a test seam iff it has at least `min_test_mentions` (1) mentions in Test files or test regions, zero in files matching `public_doc_globs` (`README*`, `docs/**`, `doc/**`, `*.1`, `man/**`, `GUIDE*`, `FAQ*`), zero in files matching `setter_file_globs` (`.github/**`, `Dockerfile*`, `Makefile`, `justfile`, `docker-compose*`, `.env*`: CI-set knobs) and no production setter; a candidate tests mention that fails one of the three is counted in a note naming the doc line, the setter file or `set by production code`.
- With git (`scan` with history, `scry declared` on a checkout) each seam, at most `max_git_lookups` in parallel, gets the birth of its read (`git log -S<NAME> -- <dirs of the read files>`, oldest) and of its first test setter (same over the dirs of the mentioning Test files): `born <h> together with its first test setter` when they match, `read born <h1>, first test setter <h2>` otherwise.
- One line per name, sorted by test mentions desc then name: `KANSPEC_ACTOR (src/ctx.rs:49 Actor.detect) is read by production code but set only by tests (8 mentions in tests/, 0 in docs; born 988d9b5 together with its first test setter) - inject or document`, every read site listed, the test dirs as `tests/ and inline tests`. `test_seams[]` in `--json` carries name, class (`seam`), reads[] (file, line, symbol), test_mentions, test_dirs, born_read, born_test, doc_mentions[] and the line.
- Report: the DECLARED section (after CLUMPS) prints the totals line `2 of 24 declared deps orphaned (8.3%: pulldown-cmark, rusqlite) in 1 manifest; 1 of 1 features dead, 0 no-op; 4 of 33 config knobs in 8 structs unread; 6 of 14 env names read are test seams`, the notes, then ORPHANED DEPS, MISPLACED, DEAD FEATURES, UNREAD KNOBS and TEST SEAMS sub-lists (each absent when empty; `none` when nothing was found, and when no manifest, no candidate struct and no env read exists); `--top` applies per list. `report.declared` carries totals, notes, `orphans[]`, `misplaced[]`, `dead_features[]`, `noop_features[]`, `unread_knobs[]` and `test_seams[]` in `--json`. The unread-knob lines are reasons on the declaring file's hotspot (after the clumps reasons) with `unread_knobs[]` (`[section.knob, line]`; a roll-up is its section path, `[ci.homerunner, line]`) and `signals.unread_knobs`; each seam line is a reason on every file holding one of its reads with `test_seams[]` (`[name, line]`) and `signals.test_seams`; `unread_knobs + test_seams` is percentile-ranked with zero -> 0 under `[declared].weight` (0.0: the section and the reasons print, the ranking is untouched); manifests are not files and never rank. `scry declared <repo> [--json] [--top N]` prints the section and the files with unread knobs or seam reads.
- Every floor, cap, list, regex and switch above is a `[declared]` setting in `scry.toml`; `check_extras`, `import_aliases` and `tool_config_globs` are accepted for the Python and JavaScript legs and read by nothing yet.
