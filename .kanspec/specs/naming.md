# naming

## Rules
- Runs inside the metrics tree walk (`metrics::collect_units` calls `naming::unit_bindings` per unit node): no second parse, no git, no graph. Test files never rank; units inside a Rust test region are measured but left out of the file totals like every other metric.
- A binding is a `let` / assignment / `for` / `with` binding of the unit: Rust `let_declaration pattern:(identifier)` (`let _ =` has no pattern and is skipped) and `for_expression pattern:`; Python the first `expression_statement > assignment left:(identifier)` per name in the unit, `for_statement left:`, `with … as x`; TS `variable_declarator name:(identifier)` under `lexical_declaration` / `variable_declaration` (including a `for (let i…)` initializer) and `for … of/in` `left:`. Parameters, closure / lambda / arrow parameters and comprehension targets are not bindings; a nested unit's bindings are its own. With `short_name_include_pattern_bindings` the names a destructuring pattern binds (`let (a, b)`, `let Some(c) = … else`, `S { d, e: f }`, `const {p} = s`) count too; off (the default) only a bare identifier does.
- A binding is short when its name has at most `short_name_max_len` characters, is not in `short_name_allow` and does not start with `_`.
- Uses are searched in the enclosing block only (the loop body for a `for` / `with` binding, the whole statement for a `for (let i…)`), after the binding statement, depth-first in document order. A subtree that rebinds the name is skipped whole: Rust `closure_expression` whose parameters bind it, `match_arm` whose pattern binds it, and every item (`fn`, `const`, `impl`…, which see no local; lifetimes and labels are skipped as well); Python `lambda` / nested `def` whose parameters bind it, a comprehension whose `for_in_clause` target binds it, an `except … as` / `case` pattern binding it; TS an arrow / function / method whose parameters (a bare `t => …` parameter included) bind it, a `catch (e)`. A construct that rebinds the name but evaluates something in the outer scope first keeps those reads: Rust `if` / `while` whose `let_condition` (or let chain) binds it search the let values and plain conditions up to the binding one and the `else` branch (`if let Some(t) = t.next() {…} else { t.reset() }` reads the outer `t` twice) and skip the body; a Rust `for`, Python `for` and TS `for … of/in` binding it search the iterable only; a Python `with … as` binding it searches the context expressions only. A later `let` / assignment / `variable_declarator` of the same name in a block ends the range in that block: its value is searched (it reads the old name), nothing after it in the block counts; a Python nested `def` / `class` of the name ends it the same way. A Python walrus rebinds too; a Python `attribute` name and `keyword_argument` name are never uses, and an attribute / subscript / member target (`self.p = p`, `d[p] = 1`) binds nothing: its `p` is a use. Any other `identifier` (TS also `shorthand_property_identifier`) with equal text is a use, macro token trees included.
- Per short binding: `decl_line`, `last_line`, `uses` (sites after the declaration), `max_gap` (the largest line distance between two consecutive uses, the declaration counting as the first) with `gap_from` / `gap_to`, `span` (`last_line - decl_line`, JSON only, gated on nowhere) and `block_lines`. A binding is far-lived when `max_gap >= short_name_min_gap`.
- Per unit (`FunctionMetrics`): `bindings` (every binding, short or not), `short_bindings[]` (left out of JSON when empty) and `long_short_bindings`, the far-lived count, which is 0 when the unit binds fewer than `short_name_min_other_bindings` other names (`bindings <= short_name_min_other_bindings`). Per file (`FileMetrics`, production units only): `bindings`, `short_bindings`, `long_short_bindings` and, with `emit_short_binding_share`, `short_binding_share = short_bindings / bindings` (0 with no binding).
- The report attaches the attribute to production units it already ranks: over `[metrics].cognitive_hard`, in the file's `worst_functions`, or at least `min_unit_lines` long. Wording: `close (lines 687-944): this block is too long to carry a one-letter name: p (declared line 690, last used line 884, 10 uses, widest gap 122 lines between lines 757 and 879, in a 258-line block)`, then `; 3 one-letter bindings have a use gap of 30+ lines: p, o, h` (widest gap first) when the unit has two or more. It never says "rename". When the file has a `N function(s) over cognitive K` reason the lines are its sub-lines (after the phase sub-lines, widest gap first); otherwise they hang under `2 function(s) carry a one-letter name across a use gap of 30+ lines`. Never a standalone reason for a unit outside those three gates; promotion needs a validation run on kanspec showing no accumulator among the flagged bindings.
- `signals.long_short_bindings` and `signals.short_binding_share` (absent when the emit knob is off) ride every hotspot; the share is percentile-ranked with weight `weight_into_complexity` (0 by default: the only route into the composite), and never becomes a reason.
- `scry metrics` prints `1799 bindings, 352 one-letter (19.6%), 9 with a use gap of 30+ lines` under its header; `--json` carries every unit's `short_bindings[]`.
- Every knob lives under `[naming]` in `scry.toml`: `short_name_max_len` 1, `short_name_allow` [i, j, k, n, x, y, z, _], `short_name_min_gap` 30, `short_name_min_other_bindings` 2, `short_name_include_pattern_bindings` false, `min_unit_lines` 100, `emit_short_binding_share` true, `weight_into_complexity` 0.0.
